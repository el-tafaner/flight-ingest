# v0.5: el cliente HTTP anónimo de OpenSky

- **Fecha:** 2026-11-07
- **Tag:** `v0.5`
- **Qué queda funcionando:** `OpenSkyClient` implementa `FlightSource`: pide una caja geográfica a OpenSky, interpreta el resultado con el parser de v0.4 y devuelve también los créditos que quedan. Un ejemplo ejecutable (`cargo run --example watch`) lo prueba contra la API real.

## Objetivo

Conectar el parser con la red sin que la red contamine el resto del código. El resto del programa solo conoce el trait `FlightSource`; el cliente HTTP es un detalle intercambiable.

## Qué construimos

- `BoundingBox`: una caja validada, con el coste en créditos que tiene consultarla.
- `OpenSkyClient`: cliente anónimo con tiempo máximo de espera y `User-Agent` propio.
- Cuatro errores nuevos en `IngestError`: caja inválida, red, límite de peticiones (`RateLimited`) y estado HTTP inesperado.
- `Snapshot::credits_remaining`: los créditos que quedan tras cada lectura.
- Tests contra un servidor HTTP falso y local.

## Por qué así

- **No existe la consulta "mundial".** El constructor exige una caja. Según la documentación de OpenSky, el coste sube con el área (de 1 a 4 créditos), y el cupo anónimo es pequeño; hacer imposible el caso caro por accidente es mejor que documentarlo.
- **El 429 es un error con tiempo de espera.** `RateLimited { retry_after_secs }` lleva el dato que necesitará el polling de v0.7 para saber cuánto esperar. Un error genérico lo perdería.
- **Los créditos viajan con el resultado.** Quien llame puede decidir cuándo volver a preguntar sin hacer una llamada extra.
- **`Network(String)` y no el error de `reqwest`.** Por el mismo motivo que `MalformedJson` en v0.4: queremos errores `Clone` y comparables en los tests.
- **Tiempo máximo explícito (20 s).** Por defecto no hay ninguno, y una petición colgada bloquearía el polling para siempre.
- **Un servidor falso de 20 líneas en lugar de una biblioteca de *mocks*.** Para esto basta con `tokio`, no añade dependencias y deja ver el HTTP real que envía el cliente (los tests comprueban la ruta, los parámetros y el `User-Agent`).
- **`rustls` en lugar de la TLS del sistema.** Compila igual en cualquier máquina y en el CI, sin depender de OpenSSL.

## Viniendo de Python

| | Python (`requests`) | Rust (`reqwest`) |
|---|---|---|
| Parámetros de la URL | `params={"lamin": ...}` | `.query(&[("lamin", ...)])`, con tipos |
| Tiempo máximo | `timeout=20` (si no, espera para siempre) | `.timeout(...)` (igual: hay que pedirlo) |
| Un estado 429 o 500 | `raise_for_status()` lanza una excepción genérica | Lo miramos nosotros y devolvemos un error con significado |
| Una cabecera ausente | `headers.get(...)` devuelve `None` | `Option<T>`, y el parseo numérico también puede fallar |
| Probar sin red | `responses`, `unittest.mock` | Un servidor real en `127.0.0.1` con puerto libre |

**Propiedad y concurrencia:** `fetch` toma `&self`: el cliente se comparte entre llamadas sin copiarse, y `reqwest::Client` está pensado para reutilizarse (mantiene un *pool* de conexiones). Por eso `OpenSkyClient` es `Clone` barato.

## Qué nos falló

- **Nombre de característica equivocado.** Mi primer intento fue `cargo add reqwest --features rustls-tls`, el nombre de versiones anteriores. Con `reqwest` 0.13 el compilador de dependencias respondió:
  ```text
  error: unrecognized feature for crate reqwest: rustls-tls
  ```
  y listó las disponibles, entre ellas `rustls` y `query`. Lección: los nombres de las características cambian entre versiones mayores; hay que leer la lista que da `cargo`, no fiarse de ejemplos antiguos.

## Decisiones pendientes

- **Autenticación:** el cliente es anónimo (400 créditos al día según la documentación). v0.6 añade OAuth2, con renovación del token.
- **Cuándo volver a preguntar:** con una caja de 1 crédito y 400 al día, no se puede preguntar más de una vez cada unos 3,6 minutos de forma sostenida. Ese cálculo, y qué hacer al recibir un 429, es el trabajo de v0.7.
- **Reintentos:** el cliente no reintenta nunca. Es una decisión consciente: reintentar es política del llamador, que es quien conoce el presupuesto.
