# v0.1: el dominio y el primer tipo (`Icao24`)

- **Fecha:** 2026-11-07
- **Tag:** `v0.1`
- **Qué queda funcionando:** un tipo `Icao24` que no se puede construir con un valor inválido, con tres tests en verde.

## Objetivo

Antes de hablar con ninguna API necesitamos decidir cómo se representa un avión dentro de nuestro programa. En este hito damos el primer paso: su identificador.

Cada aeronave emite un código **ICAO24**: seis dígitos hexadecimales, por ejemplo `4840d6`. Es la clave con la que luego reconoceremos al mismo avión en cada lectura.

## Qué construimos

- `src/domain.rs` con el tipo `Icao24` y su error `Icao24Error`.
- Tres tests: acepta seis dígitos hexadecimales (y normaliza a minúsculas), rechaza longitudes incorrectas y rechaza caracteres que no son hexadecimales.
- [ADR 0001](../adr/0001-rust-como-lenguaje.md): por qué Rust.

## Por qué así

La idea es que **un `Icao24` inválido no pueda existir**. Si el resto del programa recibe un `Icao24`, ya sabe que es correcto y no necesita volver a comprobarlo.

Para conseguirlo, el tipo envuelve un `String` en un campo privado:

```rust
pub struct Icao24(String);
```

Desde fuera del módulo solo se puede crear con `Icao24::parse`, que valida. Este patrón se llama *newtype*.

## Viniendo de Python

| | Python | Rust |
|---|---|---|
| Validar al crear | En `__init__`, lanzando una excepción | `parse` devuelve `Result`: o `Ok(Icao24)` o `Err(Icao24Error)` |
| ¿Se puede saltar la validación? | Sí: se puede asignar el atributo después o construir el objeto de otra forma | No: el campo es privado y la única puerta de entrada es `parse` |
| El error en la firma | No aparece; hay que leer la documentación | Aparece en el tipo de retorno y el compilador obliga a tratarlo |
| Comparar objetos | Hay que implementar `__eq__` y `__hash__` | `#[derive(PartialEq, Eq, Hash)]` lo genera |

Y un adelanto de **propiedad y préstamos**: `parse` recibe un `&str` (un préstamo, solo mira el texto) y devuelve un `Icao24` que contiene su propio `String`. Esa copia es lo que le permite vivir independiente del texto original. Lo desarrollamos en el siguiente hito.

## Qué nos falló

- **`cargo fmt --check` falló** por una línea en blanco sobrante al final de `domain.rs`. Se arregló con `cargo fmt`. En un proyecto público conviene automatizarlo más adelante con CI para que no dependa de acordarse.

## Decisiones pendientes

- `Icao24Error` es un `enum` escrito a mano. En **v0.3** lo cambiaremos por `thiserror`, y explicaremos qué ahorra y qué esconde.
