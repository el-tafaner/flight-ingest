# v0.2: `FlightState`, `Position` y los datos que faltan

- **Fecha:** 2026-11-07
- **Tag:** `v0.2`
- **Qué queda funcionando:** el estado completo de un vuelo, con una posición que no admite coordenadas imposibles, y ocho tests en verde.

## Objetivo

Ya tenemos el identificador del avión (v0.1). Ahora necesitamos el resto: dónde está, a qué altura, a qué velocidad, qué código de emergencia emite. Es el tipo central que usará todo lo demás.

## Qué construimos

- `Position`: latitud y longitud validadas (-90 a 90 y -180 a 180).
- `FlightState`: un struct con los campos del vuelo, casi todos opcionales.
- `callsign_trimmed()`: el indicativo sin los espacios de relleno.

## Por qué así

- **`Position` repite el patrón de `Icao24`:** campos privados y un único constructor que valida. Una posición inválida no puede existir.
- **Casi todo es `Option`:** la API devuelve `null` con frecuencia (un avión sin posición, sin `squawk`...). Modelarlo con `Option` evita valores centinela como `0` o `-1`, que se confunden con datos reales.
- **Unidades en el nombre del campo** (`baro_altitude_m`, `velocity_ms`): es lo más simple por ahora. Un tipo por unidad sería una mejora posterior.
- **Sin validar plausibilidad todavía:** altitudes o velocidades imposibles quedan para v0.3. Aquí solo se comprueba lo que se puede garantizar al construir.

## Viniendo de Python

| | Python | Rust |
|---|---|---|
| Dato que puede faltar | `None`, en cualquier variable | `Option<T>`: hay que decidir qué hacer si falta antes de usar el valor |
| Error por olvidarlo | `AttributeError` en ejecución | No compila |
| Quitar espacios de un texto | `strip()` crea un texto nuevo | `trim()` devuelve un `&str`, un préstamo de lo que ya existe, sin copiar |
| Quién libera la memoria | El recolector de basura | El dueño: al desaparecer el `FlightState`, se libera su `callsign` |

**Propiedad y préstamos en la práctica:** `FlightState` es dueño de su `callsign`. `callsign_trimmed()` devuelve un `Option<&str>` que apunta a ese texto sin copiarlo, y por eso ese valor **no puede vivir más que el `FlightState` del que sale**. El compilador lo vigila.

También hay un detalle con `NaN`: `(-90.0..=90.0).contains(&lat)` es falso para `NaN`, así que el test que lo rechaza pasa sin código extra.

## Qué nos falló

Al probar el ejercicio de abajo, el compilador devuelve esto (en la versión 1.75 de `rustc`; en versiones más nuevas el texto puede variar un poco):

```text
error[E0597]: `state` does not live long enough
   |
   |         let state = FlightState { ... };
   |             ----- binding `state` declared here
...
   |         trimmed = state.callsign_trimmed();
   |                   ^^^^^ borrowed value does not live long enough
   |     }
   |     - `state` dropped here while still borrowed
   |     println!("{:?}", trimmed);
   |                      ------- borrow later used here
```

Se lee de abajo arriba: usamos `trimmed` después de que `state` haya desaparecido, y `trimmed` apuntaba a algo de `state`.
